# v0.11.7 - 本地更新渠道与跨平台稳定性

本版本完成本地维护版更新渠道迁移，并继续收紧浏览器标签、窗口恢复和验证基础设施。已安装的 0.11.6 仍使用旧更新地址，因此需要手动安装一次 0.11.7；后续版本即可使用新渠道检查更新。

## 本地版更新

- 自动更新源迁移到 `KouriVar/Craft-Agents` 的 GitHub Latest Release，同时继续使用 generic provider，避免本地版 tag 被误判为预发布版本。
- Windows 继续支持自动下载、退出安装和重新启动。
- Linux AppImage 自动替换前会验证 `APPIMAGE` 环境；环境无效或更新失败时提供明确的手动下载恢复入口。
- 未正式签名的 macOS 构建发现新版本后提供“打开 GitHub Release”按钮，改为手动下载安装，不影响 Windows 和 Linux 的自动更新能力。
- Windows、macOS 和 Linux 分别读取 `latest.yml`、`latest-mac.yml` 和 `latest-linux.yml`，版本判断以清单内的 `version` 字段为准。

## 浏览器与窗口稳定性

- `BrowserPaneManager` 新增独立的标签生命周期协调，处理重复创建、关闭回滚、最后标签替换、迟到事件和连续崩溃恢复，同时保持外部调用方式不变。
- 关闭最后一个应用窗口不再等同于退出；macOS 点击 Dock、Windows/Linux 再次点击固定图标或启动快捷方式时，会恢复现有窗口或按上次工作区创建新窗口。
- 窗口引用已经失效时，激活请求不会再被旧引用吞掉；选择“退出/Quit”仍会执行完整资源清理并真正结束应用。

## 验证与维护

- 恢复版本一致性、i18n 新缺口、裸 IPC 白名单和 Task/Agent 工具命名检查。
- `my-changes` 的 push 和 PR 会触发 Ubuntu 快速检查，Windows/macOS 运行 Electron 类型检查与关键回归测试。
- 文档工具测试增加明确超时和失败信息，避免 bundled uv/Python 环境准备阶段无限等待。
- 更新策略、浏览器标签生命周期、窗口激活、BrowserPaneManager 和 Renderer 工作区生命周期回归测试通过。
- Electron 类型检查以及 main、preload、renderer、resources 和 subprocess 正式构建与资源校验通过。
