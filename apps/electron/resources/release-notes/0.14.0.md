# v0.14.0 - 消息平台精简、体验修复与工程收敛

本版本将消息接入收敛到实际在用的平台，清理多轮二次开发留下的死代码与协议残留，并继续修补日常使用中的体验问题。通用消息网关架构保留，后续仍可按 Adapter 方式扩展新平台。

## 破坏性变更

- **移除 WhatsApp 与 Telegram** — 应用不再提供 WhatsApp / Telegram 的连接、配对、收发与设置入口。现役消息平台为**飞书 / Lark**与**微信**。若工作区仍保存旧的 WhatsApp / Telegram 配置或绑定，启动时会安全忽略并记录一次提示，不会阻塞微信与飞书，也不会反复重试已删除平台。

## 改进

- **消息平台聚焦** — 设置页、会话菜单与配对流程只保留飞书与微信；通用连接状态、绑定、访问控制与配对能力继续由消息网关统一承载。
- **安装包更轻** — 不再打包 WhatsApp Worker（Baileys）与 Telegram Bot SDK（grammy）相关资源，减少无关子进程与依赖体积。
- **中文输入修复** — 修复切到其他 app 再切回 Craft Agents 后，中文输入首字符脱离 IME 组合的长期体验问题。此前输入拼音时第一个字母经常被当作普通字符插入（例如「changjiang」变成「c hang j iang」），现在切换应用后回来输入法不再跑偏。
- **设置 → 标签创建体验** — 「标签层级」与「自动应用规则」统一为同一「添加」按钮样式。创建标签不再弹出对话框，改为标题下方内联编辑：输入名称、选择现有系统色（accent / info / success / destructive / foreground），右侧按钮在「添加 / 取消 / 保存」间切换；支持根标签与行内添加子标签，层级树与自动规则编辑能力保持不变。
- **README 重写** — 能力概览补上探索工作台、Cowart 画布、MCP Apps Widget、浏览器扩展、密码管理、Git 工作流、项目长期记忆、插件市场等已实现能力；消息接入说明同步为飞书与微信。

## 工程与维护

- **死代码与协议表面清理** — 移除无引用的孤儿 UI 组件、重复 onboarding 副本、未装配的 TipTap 扩展、无用依赖，以及已证明无发送方的死 RPC 常量（含早期 WhatsApp 子进程 RPC 壳、`LLM_Connection:refreshModels` 独立通道、`onboarding:validateMcp` RPC 壳）；现役保存路径内的模型刷新与 MCP 校验库函数保留。
- **测试与构建稳定** — 加强跨 suite 测试隔离，收敛 Electron 生命周期与 WhatsApp 遗留启动路径后的退出清理；版本统一为 `0.14.0`，IPC 通道穷尽、i18n parity / coverage、正式构建验证通过。

## 迁移说明

- 已连接**飞书**或**微信**的用户：无需操作，能力与绑定保持不变。
- 仅使用过 **WhatsApp / Telegram** 的用户：相关入口消失；旧 binding / config 不会被当成飞书或微信，也不会导致启动失败。如需继续用消息入口，请改用飞书或微信重新连接。
- 自动化里历史上的 Telegram forum topic 字段不再生效；与飞书 / 微信无关的自动化任务不受影响。
