# Craft Agents v0.16.0 开发规划

> 版本主题：**隐私控制、Today 收敛与资源库基础**  
> 基线：`v0.15.0`（Cognition Layer 已完成）· 分支：`my-changes`  
> 阶段：**Plan / Audit（本文件）→ 人工评审修订中 → 确认后进入 Phase B**  
> 日期：2026-07-24（修订同日）  
> 状态：**规划整体通过；本轮仅修订规划文档，仍禁止修改业务代码**

---

## 0. 关键结论（先读）

1. **v0.15.0 已具备认知管道**（Event → Observation → Loop → Reflection → Guidance），但**没有隐私策略层**：关闭 Explore 开关只影响 UI 展示，Session/Git/Browser 仍持续写入 `{workspace}/cognition/`。
2. **Today 实际是三条并行建议线**：规则 Today（`buildTodayTasks`）、Cognition Guidance（`GuidanceSection`）、Explore Brief（工作概览 + 下一步推荐）。三者证据模型不统一，同一会话可重复出现。
3. **最近使用目前没有独立 UI**：`recentSessions` / `recentTabs` 只作为 Brief 输入与 fallback；`today.reason.recent` 却会把「今日聊过」塞进待处理，与 P1「最近 ≠ 待处理」冲突。
4. **资源库尚不存在**。现有 `packages/shared/src/resources/` 是 **ResourceBundle**（sources/skills/automations 导出包），命名冲突；最接近能力是 `projects/*/assets` + TipTap + PDF/Markdown 预览。
5. **Privacy Filter 必须落在 `CognitionEventStore.appendEvent` 单一写入口之前**，并同步约束读路径（Today 聚合、Explore Brief、文档生成）。禁止只在页面加开关。`CognitionEventStore` **不得自行读取 preferences**，策略由 `PrivacyService` / `PolicyResolver` 注入。
6. **文档应落在 `{workspaceDataRoot}/library/`**（与 `cognition/` 并列）；`documents/{id}.meta.json` 为元数据权威；`resources.index.json` 仅为可重建缓存。
7. **实施必须分 Phase B→C→D→E**；P0 验收通过前不得叠加资源库。资源库高级同步（Proposal/Diff）下沉到 **v0.16.x**，不得阻塞 v0.16.0。
8. **Today 相关开关必须四分**：上下文感知总开关 ≠ Today 是否可用上下文 ≠ Explore 是否显示整个 Today 区域 ≠ 会话模式输入框显示。

## 1. 版本目标与非目标

### 1.1 目标

| 优先级 | 模块 | 目标 |
|--------|------|------|
| **P0** | 设置 → 隐私 | 上下文感知总开关、细粒度来源权限、Privacy Filter、临时隐私模式、访问日志、派生数据清理 |
| **P1** | Today 收敛 | 仅保留「可选输入框 / 待处理 / 最近使用」；Today 显示总开关；合并规则任务与 Guidance；Snooze；单一 RPC「完成并归档」 |
| **P2** | 资源库第一阶段 | **v0.16.0**：侧栏、创建/生成、编辑预览、会话关联跳转、Markdown 导出、基础版本；**v0.16.x**：增量同步 Proposal / Diff / 冲突（设计保留，不阻塞主版本） |

### 1.2 依赖关系

```text
隐私与上下文控制（P0）
        ↓
Today 数据访问与推荐边界（P1）
        ↓
会话内容生成和同步到资源库（P2）
```

### 1.3 非目标（v0.16.0 明确不做）

- 多人实时协作、在线文档权限、公开网页发布、云端同步平台
- Notion 式数据库、完整 Office 编辑器、模板市场
- 全类型资源管理（PDF/表格/PPT/图片作为一等资源类型）
- 多 Agent 编排、Worktree 并行执行、Computer Use
- 独立手机 App、完整全局命令栏
- 自动归档会话、自动覆盖文档、默认扫描全磁盘
- 采集 Cookie / Token / 密码 / 表单敏感值 / 完整 Diff / 页面 HTML 正文进认知层

上述能力列入 `v0.17–v0.20` 候选。

## 6. P0 详细设计：隐私与上下文控制

### 6.1 产品入口

```text
设置
└── 隐私          ← 新一级页 settings/privacy
```

调试页 `settings/cognition` 保留给高级用户；隐私页面向所有用户。

### 6.2 四类开关分层（必须区分）

Today / 隐私相关控制**不得合并成一个开关**。权威分层如下：

| # | 开关 | 建议键 | 存放 | 默认（升级用户） | 关闭后效果 | 不影响 |
|---|------|--------|------|------------------|------------|--------|
| A | **上下文感知总开关** | `privacy.contextAwarenessEnabled` | 隐私策略（用户级，可工作区覆盖） | `true` | 停止新采集、停止认知处理、停止向模型发送上下文派生分析 | 手动会话；已有数据不自动删 |
| B | **Today 是否允许使用上下文** | `privacy.today.useContext` | 隐私策略 | `true` | 待处理**不得**消费 Guidance/Loop/Observation/浏览器/Git 等认知证据；可仅保留纯本地强信号（提醒到期、明确 overdue 等，仍受细粒度会话 meta 权限约束） | 不停止后台采集（由 A 控制）；不隐藏整个 Today 区域 |
| C | **Explore 是否显示整个 Today 区域** | `explore.showTodaySection` | Explore 设置 | `true` | ExploreHome **不渲染**「待处理 + 最近使用」整块（输入框仍由 D 单独控制） | 不改变采集与认知处理 |
| D | **会话模式输入框显示** | `explore.showSessionComposer` | Explore 设置 | `true` | 隐藏 Explore 首页会话模式统一输入框 | 浏览器地址栏、侧栏新建、浏览器新标签 |

**组合语义（示例）：**

```text
A=off, C=on  → Today 区域可见，但无新认知建议（B 亦应视为无效上下文）
A=on,  B=off → 认知层可继续写入，Today 不读上下文派生项
A=on,  B=on, C=off → 后台照常，Explore 不展示 Today 区域
C=on,  D=off → Today 从「待处理」起展示，无顶部输入框
```

设置页归属：

- A、B → **设置 → 隐私**
- C、D → **设置 → 探索**

旧键迁移：`proactiveSuggestionsEnabled` / `cognitionGuidanceEnabled` 可读一轮；映射到 B/C 的兼容逻辑在 Phase C 落地（见 §7）。

### 6.2.1 上下文感知总开关（开关 A 细则）

字段：`privacy.contextAwarenessEnabled: boolean`（经 PolicyResolver 解析，见 §6.8）。

关闭后必须同时做到：

| 动作 | 行为 |
|------|------|
| 停止采集 | Providers 不再 append 新 Event |
| 停止处理 | `processUnprocessedEvents` / `refreshGuidance` 短路 |
| 停止展示认知建议 | 若 C=on，Today 仍可显示，但不得展示依赖上下文的认知项（与 B=off 一致） |
| 清除历史 | **不自动发生**；用户显式清理 |

手动发起的普通会话对话**始终可用**（不依赖认知层）。

### 6.3 数据来源权限矩阵（第一版）

权限值：

```text
deny | ask | allow     # 敏感读/发送/执行
boolean on/off         # 纯 UI 或低敏元数据展示
```

| 来源 | 细项 | 默认（升级用户） | 类型 | 说明 |
|------|------|------------------|------|------|
| 会话 | 标题 / 任务状态元数据 | allow | deny/ask/allow | Today 强信号需要 |
| 会话 | 正文 / 附件内容 | deny（认知默认） | deny/ask/allow | 文档生成走单独「发送到模型」权限 |
| 会话 | Checkpoint nextSteps/blockers | allow | deny/ask/allow | 已在 cognition 使用 |
| 会话 | 归档会话进入认知/文档 | ask | deny/ask/allow | |
| 浏览器 | URL + 标题（绑定会话） | allow | deny/ask/allow | 与现 Event 一致 |
| 浏览器 | 页面正文 / 历史 / 下载 / Cookie | deny（禁止默认） | deny 固定或 deny/ask | Cookie/Token **永不 allow 进认知** |
| Git | 状态 / 分支 / 动作元数据 | allow | deny/ask/allow | |
| Git | Diff / 文件全文 | deny | deny/ask/allow | 与 sanitizer 一致 |
| 本地文件 | 授权目录元数据 | ask | deny/ask/allow | 禁止默认全盘扫描 |
| 本地文件 | 文件正文 | ask | deny/ask/allow | |
| 消息 | 微信 / 飞书进认知 | deny | deny/ask/allow + 可选联系人白名单（模型预留） | |
| 自动化 | 完成/失败元数据进认知 | deny（因未接入，默认关） | deny/ask/allow | |
| MCP/插件 | 主动分析 | deny | deny/ask/allow | |
| 项目 MEMORY.md | 读入认知 | ask | deny/ask/allow | |
| 资源库 | 文档生成调用模型 | ask | deny/ask/allow | P2 依赖 |
| UI | Explore 显示整个 Today 区域 | on | boolean | 开关 C，见 §6.2 |
| UI | 会话模式输入框显示 | on | boolean | 开关 D，见 §6.2 / §7.2 |

**布尔开关适用：** 纯展示（Today 区域、输入框、调试面板可见性）。  
**三级权限适用：** 读取敏感正文、向模型发送、执行修改（未来）。

### 6.4 Privacy Filter 管线

逻辑管线：

```text
Source Event
  → Privacy / Context Policy（decide: allow | deny | ask）  ← 注入的 resolved policy
  → Sanitization（现有）
  → Allowed Event → Observation → …
```

**拦截结果：**

- `deny`：不写 ledger；写访问日志（被拦截）
- `ask`：v0.16 第一版对后台被动采集按 **deny** 处理，并在隐私页提示「需手动允许」；交互式路径（文档生成）弹窗询问
- `allow`：进入 sanitizer

**已入认知层的历史数据：** 保留在磁盘；消费侧按当前策略 + `sourceKinds` 过滤；不自动删除。

### 6.5 认知派生数据的来源传播（读写过滤）

权限关闭后不能只靠「停写」；**读路径必须能过滤已经生成的派生数据**。

#### 6.5.1 必须持久化的来源字段

| 实体 | 现有（v0.15） | v0.16 必须 |
|------|---------------|------------|
| Observation | 已有 `sourceEventIds: string[]` | 新增 **`sourceKinds: CognitionEventSource[]`**（由源 Event 的 `source` 去重聚合，通常长度 1） |
| Loop | 有 `observationIds`；无直接 event 来源种类 | 新增 **`sourceEventIds`**（从关联 Observation 传递并去重）+ **`sourceKinds`** |
| Reflection | 有 `sourceObservationIds` / `sourceLoopIds` | 新增 **`sourceEventIds`** + **`sourceKinds`**（并集传递） |
| Guidance | 有 `sourceObservationIds` / `sourceLoopIds` | 新增 **`sourceEventIds`** + **`sourceKinds`**（并集传递） |

`CognitionEventSource` 沿用现有：`'session' | 'task' | 'git' | 'browser' | 'automation' | 'messaging' | 'system'`。

传递规则（生成时强制）：

```text
Event.source
  → Observation.sourceKinds = [event.source]
  → Observation.sourceEventIds = [event.id]
  → Loop / Reflection / Guidance：union(child.sourceEventIds), union(child.sourceKinds)
```

重建 Guidance / refresh 时必须重新计算并写回，不得丢字段。

#### 6.5.2 读路径过滤

所有面向 Today / Debug 消费面以外的产品读路径（Pending 聚合、listGuidance 供 Today、证据展开）必须：

```ts
function isReadableByPolicy(entity: { sourceKinds?: string[] }, policy: ResolvedPrivacyPolicy): boolean {
  if (!policy.contextAwarenessEnabled || policy.privacyMode.active) return false // 或仅允许非上下文本地信号
  if (!policy.today.useContext) return false // 开关 B：Today 读路径
  const kinds = entity.sourceKinds?.length ? entity.sourceKinds : ['unknown']
  return kinds.every((k) => sourceKindAllowed(policy, k))
}
```

- 关闭某一来源（如 `browser`）后：含 `browser` 的 Observation/Loop/Guidance **对新读不可见**（磁盘仍在）。
- 混合来源实体：任一 `sourceKind` 被 deny → 整条对产品读路径隐藏（保守策略，避免半泄漏）。
- Cognition Debug 页可提供「显示被策略隐藏的项」高级开关（默认关），便于排障。

#### 6.5.3 v0.15 数据缺少 `sourceKinds` 的兼容策略

| 情况 | 策略 |
|------|------|
| Observation 有 `sourceEventIds` 无 `sourceKinds` | **懒修复**：读时用 eventId 查 ledger 回填 `source`；写回 store（可选批量 migration） |
| Loop/Reflection/Guidance 无 `sourceEventIds`/`sourceKinds` | 经 `observationIds` / `sourceObservationIds` / `sourceLoopIds` 回溯；能解析则回填；**无法解析则 `sourceKinds = ['unknown']`** |
| `unknown` 的可见性 | 默认：**对产品 Today 隐藏**（fail-closed）；Debug 可见。避免「关了浏览器权限仍看到旧浏览器建议」 |
| 全量迁移 | Phase B 提供一次性 `cognition:backfillSourceKinds`（或启动时限速 backfill）；失败不阻断启动 |
| schema | `COGNITION_SCHEMA_VERSION` 升到 2；`migrationsApplied` 记录 `cognition-1-to-2-source-kinds` |

  activatedAt?: number
  resumeAt?: number | null  // 预留定时恢复，v0.16 可不实现 UI

### 6.8 Privacy Policy 依赖注入边界

**硬约束：`CognitionEventStore` 不得自行读取 `preferences.json` / 工作区文件来解析策略。**

```text
┌─────────────────────────────────────────────────────────────┐
│ PrivacyService (server-core)                                │
│  - 加载用户 preferences.privacy                             │
│  - 合并工作区 {workspace}/privacy/policy.json 覆盖          │
│  - 合并内存中的隐私模式状态                                 │
│  - 产出 ResolvedPrivacyPolicy（不可变快照）                 │
└───────────────────────────┬─────────────────────────────────┘
                            │ inject PolicyResolver / getPolicy()
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ CognitionService                                            │
│  - 构造 CognitionEventStore 时注入 resolvePolicy            │
│  - append 前 decide；读 list* 时 filter                     │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ CognitionEventStore (shared)                                │
│  - 仅接受：() => ResolvedPrivacyPolicy | PolicyDecision     │
│  - 或构造参数 policyGate: { decide(input) => Decision }     │
│  - 无 fs 读 preferences；无 Electron 依赖                  │
└─────────────────────────────────────────────────────────────┘
```

| 组件 | 允许 | 禁止 |
|------|------|------|
| `PolicyResolver` / `PrivacyService` | 读 preferences、工作区覆盖、隐私模式状态；写 access-log | 直接 append events |
| `CognitionEventStore` | 调用注入的 `decide`；sanitize；落盘 | 读 preferences、读工作区 policy 文件、猜默认策略绕过注入 |
| Providers (Git/Browser) | 调 `CognitionService.appendEventSafe` | 自己读 preferences 决定是否 emit（可可选短路，但最终仍以 store 门为准） |
| Renderer | 经 RPC 读写策略 / 模式 | 本地复制一套策略决定是否「算进认知」 |

**策略优先级（高 → 低）：**

```text
1. 临时隐私模式（privacyMode.active）
2. 工作区覆盖（{workspace}/privacy/policy.json）
3. 用户设置（~/.craft-agent/preferences.json → privacy）
4. 内置默认值（DEFAULT_PRIVACY_POLICY）
```

字段级合并：工作区只覆盖声明的字段；未声明字段继承用户设置；隐私模式为运行时覆盖层（不改持久配置，除非用户选择「持久化隐私模式」）。

单测要求：store 在注入 `decide → deny` 时不落盘；未注入 policyGate 时测试环境使用显式 `allowAll` 或 `denyAll` fixture，**禁止**隐式读真实 preferences。

### 6.9 数据管理

隐私页提供：

- 清除认知数据（复用/扩展 `cognition:clear`，按类型）
- 清除访问日志
- 清除 Today 缓存（含 Explore Brief localStorage）
- 清除浏览器上下文（认知侧 browser events；**不**删 Electron browser-profile，除非单独确认）
- 清除会话派生数据（Observation/Loop/… 与 sessionId 关联）
- 按工作区 / 类型清除
- 存储占用估算
- 保留周期设置

**硬约束：** 清除认知/日志 **不得**删除原始 `session.jsonl`、项目 assets、资源库文档。

### 7.3 待处理（PendingQueue）

仅在 **C=on** 时渲染。内容还受 **A/B** 与细粒度 `sourceKinds` 过滤约束（§6.5）。

**聚合源（内部）：**

| 源 | 信号强度 | 说明 |
|----|----------|------|
| taskReminder due | 强 | 本地会话 meta；B=off 时仍可保留 |
| overdue / dueToday | 强 | 同上 |
| failed / waiting/blocked | 强 | 同上 |
| Checkpoint nextSteps | 强 | 会话 meta；非认知派生 |
| open/blocked Loop + Guidance | 强 | **需要 B=on 且 sourceKinds 可读** |
| 用户任务目标未完成 | 强 | 本地 meta |
| Explore Brief / AI「可能值得继续」 | 弱 | 默认不进队；**归档建议仅建议** |
| recent 聊天 / 最近打开网页 | **不进待处理** | 进「最近使用」 |

**用户可见字段：** 名称、为什么出现、状态、推荐动作、来源会话、截止/优先级（可选）。  
**禁止暴露：** Observation/Loop/Guidance 等内部术语（「查看判断依据」可展开内部证据）。

**主操作：** 继续处理 · 完成并归档 · 稍后处理  
**更多：** 仅归档 · 标记完成 · 保留但不再提醒 · 忽略本次建议 · 查看判断依据

### 7.4 去重

统一 `PendingItem.id` 策略：

```text
primaryKey = sessionId ?? `loop:${loopId}` ?? `guidance:${guidanceId}`
```

同一 `sessionId` 只保留最高分一条；合并 reason 标签。  
Guidance 已有 `excludeSessionIds` 思路，升级为聚合器第一公民。

### 7.5 稍后处理（Snooze）

**独立状态，不复用 `taskReminder*`。**

```ts
TodaySnooze {
  schemaVersion: 1
  targetKey: string          // sessionId or pendingKey
  until: number | null       // null = 暂时不再提醒（与 dismiss 区分：可配置时长）
  createdAt: number
  source: 'user'
}
```

存储：`{workspace}/today-state.json`（推荐；属 Today 产品态，非认知衍生，**不要**放进 `cognition/`）。

关系：

| 机制 | 用途 |
|------|------|
| `taskReminder*` | 用户设定的任务提醒 |
| Guidance `dismissedAt` | 永久忽略该建议目标 |
| Loop dismissed/resolved | 认知闭环状态 |
| **Snooze** | Today 队列临时隐藏 |

Snooze 期间聚合器跳过；到期后可再入队；**不得**因 Cognition rebuild 立即复活重复卡片（结合 snooze until）。

### 7.6 完成并归档（单一 server-core RPC）

**禁止 Renderer 串联** `setSessionStatus` + `resolveLoop` + `dismissGuidance` + `archiveSession` 等多个 RPC。

#### 协议

```ts
// RPC_CHANNELS.sessions.COMPLETE_AND_ARCHIVE = 'sessions:completeAndArchive'

interface CompleteAndArchiveRequest {
  workspaceId: string
  sessionId: string
  options?: {
    createFinalCheckpoint?: boolean  // 默认 true
    resolveOpenLoops?: boolean       // 默认 true
    dismissGuidance?: boolean        // 默认 true
    clearTodaySnooze?: boolean       // 默认 true
  }
  /** 客户端幂等键；同一 key 重试返回同一逻辑结果 */
  idempotencyKey?: string
}

interface CompleteAndArchiveStepResult {
  step:
    | 'mark_done'
    | 'create_checkpoint'
    | 'resolve_loops'
    | 'dismiss_guidance'
    | 'archive'
    | 'clear_snooze'
  status: 'ok' | 'skipped' | 'failed' | 'already_done'
  detail?: string
  errorCode?: string
}

interface CompleteAndArchiveResponse {
  sessionId: string
  ok: boolean                 // 全部必须步骤成功（archive 必须 ok 才为 true）
  alreadyCompleted: boolean   // 幂等：会话已归档且已 done
  steps: CompleteAndArchiveStepResult[]
}
```

#### 后端统一顺序（server-core）

```text
1. mark_done          → sessionStatus/kanbanColumn = done
2. create_checkpoint  → 可选；失败记 failed，不阻断后续（可配置）
3. resolve_loops      → 该 session 下 open/waiting/blocked loops → resolved
4. dismiss_guidance   → 指向该 session 的 active guidance → dismissed
5. archive            → archiveSession（必须成功才整体 ok）
6. clear_snooze       → today-state 中相关 snooze 清除
```

#### 幂等与失败语义

- 已 `done` + 已 `archived`：返回 `alreadyCompleted=true`，各步 `already_done` / `skipped`，`ok=true`
- 中途失败：已成功步骤保留；`ok=false`；返回完整 `steps[]`；客户端可原样重试（依赖 idempotencyKey + 逐步 already_done）
- **不**静默回滚已归档；归档失败则不得声称成功
- 不自动改资源库文档
- Renderer：**只调用一次** `completeAndArchive`；根据 `steps` 展示 toast/部分失败 UI

### 7.7 最近使用

仅在 **C=on** 时渲染。

- 会话：复用 `recentSessions`（过滤 hidden/archived/deleted）
- 网页：复用 browser tabs 持久化（过滤 about:blank / 失效）
- 纯导航；无 AI 摘要；数量上限建议会话 8 + 网页 8
- 点击恢复原位置（现有 `onOpenSession` / `onOpenTab`）
- **不**因出现在最近使用而进入待处理

|------|------|
| 首页工作概览卡片 | 删除 |
| 下一步推荐区块 | 删除 |

### 8.5 关联、来源锚点与增量同步

#### 8.5.1 文档来源引用（修正：不用不稳定 blockId）

**问题：** 纯 Markdown / TipTap 文档**没有**稳定的运行时 `blockId`；按编辑器内部 id 或标题文本索引会在用户改标题后失效。

**v0.16.0 裁决：嵌入 Markdown 的稳定 section anchor（章节级）。**

生成或关联时，在对应章节标题行写入 HTML 注释锚点（对渲染不可见、可随文件版本管理）：

```markdown
## 决策结论
<!-- craft-section:sec_01J… -->

正文…

## 下一步
<!-- craft-section:sec_01J… -->
```

规则：

- `sectionId` = ULID/UUID，**生成后永不因标题改名而改变**
- `DocumentSourceReference` 使用 `sectionId`，**不**使用脆弱的 `blockId`
- 第一版**仅章节级**引用（`messageIds[]` 挂在 section）；**不做字符级 / 行级引用**
- 用户删除锚点注释 → 该引用变为 `orphaned`（meta 中标记），UI 提示「来源锚点已丢失」
- TipTap 序列化必须保留这些 HTML 注释（实现时加回归测试）

备选（不采用为默认）：旁路 offset 映射表 — 更容易因编辑漂移，仅作未来研究。

```ts
interface DocumentSourceReference {
  schemaVersion: 1
  documentId: string
  sectionId: string              // 对应 <!-- craft-section:... -->
  sessionId: string
  messageIds: string[]
  headingSnapshot?: string       // 可选，仅便于 UI 显示，不作主键
}
```

#### 8.5.2 会话关联与跳转（v0.16.0）

- 文档页展示关联会话：标题、关联时间、上次同步消息（若有）、打开会话
- 点击跳转原会话，尽可能定位到 `messageIds[0]`
- 返回文档时保持阅读位置（renderer 路由状态）
- 解除关联写入 meta（权威源）

#### 8.5.3 增量同步（完整设计保留 → **v0.16.x 实现**）

```text
检测到未同步消息
  → 用户点击同步
  → 只读取上次同步后的新增内容
  → 生成 DocumentSyncProposal
  → 用户审阅 Diff
  → 确认后写入 + 新版本
```

- `DocumentSessionLink`：sync cursor（lastMessageId + time）、pendingCount
- **禁止**默认实时覆盖
- 多会话关联 / 一会话多文档：模型 v0.16.0 支持；同步 UX 在 v0.16.x
- v0.16.0 可展示「上次生成/同步游标」只读信息，但不做 Proposal 流

### 8.6 元数据权威来源与索引缓存

**裁决：`documents/{id}.meta.json` 为唯一权威；`resources.index.json` 仅为可重建索引缓存。**

```text
{workspaceDataRoot}/library/
  manifest.json                 # schemaVersion, migrationsApplied
  resources.index.json          # 缓存：列表字段投影，可删除后重建
  documents/{id}.md             # 正文（含 craft-section 锚点）
  documents/{id}.meta.json      # ★ 权威：Document + links + sourceRefs + sync 游标摘要
  versions/{documentId}/{versionId}.md
  versions/{documentId}/{versionId}.meta.json   # 版本说明（可选合并进版本清单）
  sync-proposals/{id}.json      # v0.16.x
```

| 操作 | 权威写入 | 索引 |
|------|----------|------|
| 创建/更新/归档/删除文档 | 写/更新/删 `documents/{id}.meta.json` + `.md` | 异步或同事务更新 `resources.index.json` |
| 列表/搜索 | **可**读 index；若缺失或 checksum 失败则重建 | |
| 崩溃后 index 半残 | 扫描 `documents/*.meta.json` 重建 index；以 meta 为准 | |
| 冲突（index 与 meta 不一致） | **以 meta 为准**覆盖 index 条目 | |

`resources.index.json` 建议含 `builtAt`、`sourceManifestVersion`、每条 `id/title/updatedAt/archivedAt/projectId/syncStatus/sessionCount`；**禁止**把正文塞进 index。

崩溃恢复：

1. 启动或 `library:repair`：枚举 `documents/*.meta.json`
2. 校验对应 `.md` 是否存在；缺失则标记 `bodyMissing`
3. 原子写新 `resources.index.json.tmp` → rename
4. 不自动删除用户 `.md`

### 8.7 版本（v0.16.0 基础）

触发（v0.16.0）：首次创建、用户手动保存点、恢复旧版本前快照、（可选）AI 初次生成后。  
触发（v0.16.x 追加）：同步应用、AI 改写同步。  

第一版：列表 / 预览 / 恢复；全文快照即可。

### 8.8 导出（v0.16.0）

必须：复制 Markdown、复制纯文本、导出 `.md`。  
可选：HTML；PDF（不阻塞）。  
系统分享 / 打开文件位置（桌面端）。  
无在线公开链接。

## 12. 隐私策略模型

### 12.1 决策函数与注入（伪代码）

```ts
function decide(input: PolicyInput, policy: ResolvedPrivacyPolicy): Decision {
  if (policy.effectivePrivacyModeActive || !policy.contextAwarenessEnabled) {
    if (input.feature === 'manual_chat') return allow
    if (input.feature === 'library_user_export') return allow_if_local
    return deny('privacy_mode_or_master_off')
  }
  const level = resolveSourcePermission(policy, input.source, input.aspect)
  if (level === 'deny') return deny
  if (level === 'ask' && input.interactive) return ask
  if (level === 'ask' && !input.interactive) return deny // v0.16 被动采集
  return allow
}

// CognitionEventStore 构造：
new CognitionEventStore({
  workspaceDataRoot,
  policyGate: {
    decide: (input) => privacyService.decide(workspaceId, input),
  },
})
```

优先级重申：`临时隐私模式 > 工作区覆盖 > 用户设置 > 默认值`（见 §6.8）。

Today 读路径额外门闩：`policy.today.useContext`（开关 B）与 `sourceKinds` 过滤（§6.5）。

### 12.2 与资源库

| 问题 | 答案 |
|------|------|
| 哪些会话可生成文档 | `session.meta/body` 允许或 ask 通过；归档看 `session.archived` |
| 附件 | 默认 ask/deny；单独权限 |
| 发送外部模型 | `library.generateWithModel` |
| 自动检查新增 | `library.autoDetectSync`（**v0.16.x**）且非隐私模式 |
| 清认知 | **不影响** library |
| 删会话 | 文档保留，`DocumentSessionLink.orphaned=true` |
| 导出前敏感检查 | 第一版做基础提示（可选扫描 token 模式）；不阻塞本地导出 |

## 13. 存储与迁移方案

### 13.1 选择依据

| 方案 | 结论 |
|------|------|
| 工作区内 `library/` | **采用**：与 cognition/sessions 一致，天然多工作区隔离；**meta.json 权威 + index 缓存** |
| Electron userData | 拒绝：与业务数据分裂，备份/迁移困难 |
| 项目目录（用户 Git cwd） | 拒绝作为主存储：污染用户仓库；可选「导出到项目」后续再做 |
| 混合 | 索引在 workspace，正文也可 workspace；附件引用会话 attachments 只读 |

### 13.2 迁移

- `PrivacyPolicy.schemaVersion` / `library/manifest.schemaVersion` / Today snooze schema / Cognition → v2（sourceKinds）
- 升级用户：
  - `contextAwarenessEnabled = true`（开关 A）
  - `today.useContext = true`（开关 B）
  - `showTodaySection = true` / `showSessionComposer = true`（开关 C/D）
  - 细粒度默认见 §6.3（不收紧到破坏 Today 强信号）
  - Explore 旧键兼容读取；首页不再渲染 Brief/下一步
  - **不**自动删除或改写 session.jsonl / 已有 cognition 文件；sourceKinds 懒回填 / 可选 backfill
- Cognition `ensureCognitionMigrations` 增加 `cognition-1-to-2-source-kinds`

### 13.3 命名冲突

- 产品名「资源库」↔ 代码模块 `library`
- 现有 `shared/resources`（ResourceBundle）保持不动，文档中明确区分

## 19. 风险与回滚方案

| 风险 | 等级 | 缓解 / 回滚 |
|------|------|-------------|
| 只做 UI 开关未接写路径 | **高** | Phase B 验收以「磁盘无新 event」为准；单测锁 choke point |
| Provider 绕过（Browser 在 Electron main） | **高** | 统一走 `CognitionService.appendEventSafe`；禁止直写 store |
| Today 三线残留双数据流 | **高** | Phase C 删除 Brief/Guidance 展示调用；grep 门禁 |
| `recent` 继续污染待处理 | 中 | 默认移除；测试锁 |
| Snooze 与 reminder/dismiss 冲突 | 中 | 独立 today-state；文档化优先级 |
| 完成并归档部分失败 | 中 | 单一 RPC + steps[] + 幂等重试 |
| Store 偷读 preferences | **高** | 注入边界单测；代码审阅门禁 |
| 旧派生数据无 sourceKinds 泄漏 | **高** | unknown fail-closed；backfill |
| index 与 meta 双写漂移 | 中 | meta 权威；repair 重建 index |
| 文档同步覆盖用户编辑 | **高** | **v0.16.x** 仅 proposal；先版本快照再 apply |
| 同步范围膨胀阻塞发布 | **高** | 同步流强制 v0.16.x，不进 v0.16.0 必达 |
| 清认知误删文档 | **高** | 分离目录；清理 API 白名单单测 |
| 升级用户首页「突然变空」 | 中 | 输入框默认 on；待处理保留强信号；Brief 移除需在 release notes 说明 |
| Automation/Messaging 权限超前 | 低 | 模型预留，默认 deny，不实现完整白名单 UI |
| 规则中文硬编码 | 中 | UI 层 i18n；后续再净化规则串 |

**回滚策略：**

- Feature 以 policy 默认与设置开关控制；紧急可 `contextAwarenessEnabled=true` 且放宽 source 保持 v0.15 行为
- library 目录可整体忽略而不影响会话
- 不写破坏性 session 迁移；回滚版本不自动删用户文档

## 20. 明确的验收标准

### P0

- [ ] 设置 → 隐私可管理上下文权限（含开关 A/B）
- [ ] `CognitionEventStore` 经注入决定，**不**自行读 preferences
- [ ] 关闭某来源后，**新数据不能进入认知层**（查 `events.jsonl`）
- [ ] 关闭某来源后，**已有**含该 `sourceKinds` 的派生数据对 Today/产品读路径不可见
- [ ] 关闭上下文感知（A）后，停止采集与处理；Today 不再生成认知建议
- [ ] 关闭 Today 使用上下文（B）后，待处理不消费 Guidance/Loop 等派生项

## 22. 必须回答的架构问题（明确答案）

### 1. Privacy Filter 应放在哪一层？

**答：** 策略定义与 `decide()` 放在 `packages/shared/src/privacy/`；**加载与合并**在 server-core `PrivacyService` / `PolicyResolver`；**强制执行点**在 `CognitionEventStore.appendEvent` 内、`sanitize` 之前，经**注入的** `policyGate` 调用——**Store 不得自行读 preferences**。读路径共享同一 resolved policy。

### 2. 如何保证 Session、Git、Browser、Automation 都不能绕过权限？

**答：**  
1) 禁止直写 `events.jsonl`；  
2) 唯一 `appendEvent` + 注入 gate；  
3) Providers 仅调 `CognitionService.appendEventSafe`；  
4) 单测 + 代码搜索门禁；  
5) Automation 未实现前保持 stub，未来也必须同入口。

### 3. 权限关闭后，已有认知数据如何处理？

**答：** **保留不自动删**；停止新采集与新处理；读路径按 `sourceKinds` + 当前策略过滤（缺字段按 §6.5.3 兼容，`unknown` 对 Today fail-closed）；用户显式清理。

### 4. Explore Brief、TodaySection、GuidanceSection 最终分别保留什么？

| 模块 | 最终 |
|------|------|
| Explore Brief | **内部能力可选保留，首页 UI 删除** |
| TodaySection | **演进为待处理 UI**（规则强信号；受开关 C） |
| GuidanceSection | **不再独立展示**；数据并入待处理（受开关 B + sourceKinds）；RPC/store 保留 |

### 5. 如何避免同一会话重复出现在待处理列表？

**答：** 单一 `buildPendingQueue` 聚合；`primaryKey=sessionId`；多源合并 reason；禁止 Brief 与 Guidance 各自渲染列表。

### 6. 「稍后处理」应复用提醒系统，还是建立独立 Snooze 状态？

**答：** **独立 Snooze（`today-state`）**。`taskReminder` 是用户任务提醒；`dismissedAt` 是永久忽略。三者语义不同。

### 7. 「完成并归档」如何保持事务一致性？

**答：** **单一 server-core RPC** `sessions:completeAndArchive`；后端有序执行 mark_done → checkpoint → resolve_loops → dismiss_guidance → archive → clear_snooze；返回逐步 `steps[]`；幂等；Renderer 禁止多 RPC 串联；不假装跨文件原子事务，不静默回滚已成功 archive。

### 8. 文档存储在工作区还是 userData？

**答：** **工作区 `{workspaceDataRoot}/library/`**。`documents/{id}.meta.json` 权威；`resources.index.json` 可重建缓存。

### 9. 资源库如何支持多工作区和项目关联？

**答：** 每工作区独立 `library/`；`DocumentMeta.projectId` 可选绑定；索引不跨工作区。

### 10. 文档区块如何记录来源消息？

**答：** Markdown 内嵌入稳定 `<!-- craft-section:ID -->` 锚点；`DocumentSourceReference.sectionId` 指向该锚点 + `messageIds[]`。**章节级 only**；不做字符级；不用脆弱 blockId。

### 11. 增量同步如何避免覆盖用户手动修改？

**答：** 设计保留：只生成 `DocumentSyncProposal`，先版本快照再 apply。**实现归 v0.16.x**，不阻塞 v0.16.0。

### 12. 删除原会话后，关联文档如何处理？

**答：** 文档与 meta 保留；链接标 `orphaned`；同步不可用；跳转提示会话已删除。

### 13. 清除 Cognition 数据为什么不能删除资源库文档？

**答：** 认知是系统衍生；资源库是用户产物。分属 `cognition/` 与 `library/`，清理白名单隔离。

### 14. v0.16.0 如何兼容已有用户设置与认知数据？

**答：** 开关 A/B/C/D 默认均开启；旧 Explore 键兼容映射；认知文件不删；`sourceKinds` 懒回填 / backfill；输入框与 Today 区默认显示避免突变。

### 15. 哪些功能必须砍到后续版本，防止资源库变成完整文档软件？

**答：** 协作、云权限、发布、Notion DB、Office、模板市场、全类型资源、实时同步、评论、页面嵌套——砍出 v0.16；**增量同步 UX 砍到 v0.16.x**（设计保留）。

### 16.（增补）策略优先级是什么？

**答：** `临时隐私模式 > 工作区覆盖 > 用户设置 > 默认值`。

## 26. 最大的三个架构风险

1. **隐私若只做设置 UI，采集仍写入 cognition（当前即如此）** — 必须先锁写入口 + 注入边界。  
2. **Today 三条建议线清理不彻底，或四开关语义混淆** — 导致双数据流 / 用户无法关掉展示。  
3. **文档同步若挤进 v0.16.0 或覆盖正文 / 双写 meta 与 index** — 发布风险与数据丢失。
