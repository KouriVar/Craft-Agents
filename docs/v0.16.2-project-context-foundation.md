# v0.16.2 Project Context Foundation — 架构分析与最小实现方案

> 阶段：只读架构分析（未修改任何代码）

## 1. Project 当前数据模型

### 1.1 存储位置（纯文件系统，无 DB）

```
{workspace.rootPath}/projects/{projectSlug}/
  ├── config.json   — ProjectConfig（设置）
  ├── assets/        — 上传文件（PDF/图片/文本）
  └── MEMORY.md      — Agent 长期记忆（5000 token 截断注入 prompt）
```

- 路径解析：`getWorkspaceProjectsPath(rootPath)` → `join(rootPath,'projects')`（`packages/shared/src/projects/storage.ts:41`）
- workspace.rootPath 来自 `Workspace.rootPath`（`packages/core/src/types/workspace.ts:40`），默认 `~/.craft-agent/workspaces/{slug}/`
- 读写：`loadProjectConfig`（`storage.ts:98`，`readJsonFileSync` 不校验/不默认值化）、`saveProjectConfig`（`storage.ts:123`，原子写 + bump updatedAt）

### 1.2 DTO 定义（`packages/shared/src/projects/types.ts`）

**ProjectConfig**（`types.ts:35-55`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `string` | `proj_${uuid前8位}`，跨重命名稳定（`storage.ts:296`） |
| `slug` | `string` | URL 安全文件夹名，workspace 内唯一，不可改（`storage.ts:318`） |
| `name` | `string` | 用户可见名 |
| `description` | `string?` | 列表/详情头简述 |
| `workingDirectory` | `string?` | 绑定绝对路径；新 session 未覆盖时继承 |
| `details` | `string?` | 注入系统 prompt 的自由文本 |
| `colorTheme` | `string?` | 主题 ID |
| `color` | `string?` | accent 色（hex），显示在绑定 session 行 |
| `createdAt` / `updatedAt` | `number` | 时间戳 |
| `archivedAt` | `number?` | 归档时间（字段存在，UI 无归档按钮） |
| `kanbanColumns` | `KanbanColumnDef[]?` | 自定义看板列 |

**无字段**：members、permissions/roles、sourceBindings、默认 model/thinkingLevel、icon。
**派生类型**：`LoadedProject`（config + folderPath/assetsPath/workspaceRootPath/workspaceId，`types.ts:84`）、`ProjectPromptContext`（prompt 注入用，`types.ts:100`）。

### 1.6 Workspace ↔ Project 关系

Project 是 Workspace 子级，一个 Workspace 多个 Project。**Workspace 无 projectId**（方向反了：Session 上有 projectId）。`ProjectConfig` 不持久化 workspaceId（`LoadedProject.workspaceId` 从 `basename(workspaceRootPath)` 派生，`storage.ts:210`）。

## 2. Session 与 Project 的关系

### 2.1 projectId 已存在且稳定

- `SessionConfig.projectId?: string`（`sessions/types.ts:234`），值 = `ProjectConfig.id`（`proj_xxx`）
- 持久化在 JSONL 首行（`SessionHeader`/`SessionMetadata`），列入 `SESSION_PERSISTENT_FIELDS`（`types.ts:57`）
- **跨重命名稳定**：`updateProject` 强制保留 id/slug（`storage.ts:318`），RPC patch 类型 `Omit<ProjectConfig,'id'|'slug'|'createdAt'>`

### 2.2 新建会话流程（完整，3 个 UI 入口）

- **ProjectInfoPage**「+ New session」→ `onCreateSession(workspaceId, { projectId: project.config.id })`（`ProjectInfoPage.tsx:145`）
- **Deep link** `?project=...`（`NavigationContext.tsx:743`）
- **Kanban** 项目筛选激活时新建任务自动绑定（`KanbanBoardContainer.tsx:372`）
- → `createSession` RPC（`sessions.ts:190`）→ `SessionManager.createSession`（`SessionManager.ts:2766`）
  - 子任务继承父会话 projectId（`:2773`）
  - 加载项目校验：显式传缺失 projectId **抛错**；继承的缺失 **静默 no-op**（`:2782`）
  - 继承项目 workingDirectory（仅当调用方未显式指定，`:2788`）

### 2.3 Move / Rebind / Unbind（已存在）

- 统一走 `setProjectId` 命令（`dto.ts:660`，`null`=解绑），事件 `project_id_changed`（`dto.ts:502`）
- `SessionManager.setSessionProjectId`（`SessionManager.ts:7447`）：**不改变 session 的 workingDirectory**（注释明确，仅影响新建默认值）
- **UI 入口：SessionList 右键菜单「Projects」子菜单**（`SessionMenu.tsx:219`），不在 ProjectInfoPage
- 删除 project 时主动解绑（`unbindProjectFromSessions`，`sessions/storage.ts:638`，先解绑后删目录）

### 2.4 数据兼容风险

- **给 Project 加字段**：风险低。session 只持 id 不解码 config；`loadProjectConfig` 不校验，多出字段原样保留。新字段应声明 optional。
- **悬挂 projectId**（手动删目录等）：各路径优雅降级——loadSession 原样保留、SessionList 'project' 分组降级到 `__none__` 桶（`SessionList.tsx:401`）、SessionItem 色条不渲染、ProjectInfoPage 不显示。**不崩溃**，但 session 在项目维度"孤立"。

### 2.5 按项目过滤

- ProjectInfoPage sessions tab：纯客户端 `meta.projectId === project.config.id` 过滤（`ProjectInfoPage.tsx:134`）
- SessionList 'project' 分组：未知 id → `__none__` 桶（`SessionList.tsx:401`）
- Kanban/Task 深度集成：`KanbanTask.projectId`、task spec 表单、TaskRunner、cognition/library/git 全链路按 projectId

## 3. Library 与 Project 的关系

### 3.1 当前关联（数据层已有，查询/UI 层缺失）

`projectId?` 已存在于 4 个类型（`packages/shared/src/library/types.ts`）：
- `DocumentMeta.projectId?`（`:110`，权威源）
- `LibraryIndexEntry.projectId?`（`:147`，列表缓存）
- `LibraryCreateBlankRequest.projectId?`（`:175`）
- `LibraryUpdateRequest.projectId`（`:236`，可设 `string` / 可清 `null`）

填充：`toIndexEntry()`（`LibraryService.ts:146`）、`createBlank()`（`:331`）、`createFromSessionContent()`（`:542`）、`update()`（`:614`，支持设/清）。

### 3.2 继承（自动，服务端）

从会话生成文档时**自动继承**会话 projectId（`handlers/rpc/library.ts:224` 传 `projectId: session.projectId`）。客户端 `LibraryCreateFromSessionRequest` 无需含 projectId。`createBlank` 路径目前 UI 不传 projectId（`LibraryListPanel.tsx:51`）。

### 3.3 按项目过滤（不支持）

`LibraryListQuery`（`types.ts:159`）**无 projectId 字段**。`list()`（`LibraryService.ts:256`）仅按 status/recent/search 过滤；projectId 仅在 `search` 文本子串匹配时被偶然搜到（`:272`，搜的是原始 id 串非项目名）。**无法"列出项目 X 的文档"**。

### 3.4 是否需要新增字段

- 数据字段：**不需要**（已完备，含设/清）。
- 查询字段：**需要** `LibraryListQuery` 加 `projectId?: string | string[]` + `list()` 加精确过滤分支。
- UI：`LibraryListPanel.tsx:213` 仅以裸 id 字符串显示（` · ${item.projectId}`），需改项目名/色徽章；`LibraryDocumentPage.tsx` 完全不显示 projectId。

### 3.5 结论

Library 已有项目关联的数据层（含自动继承），**数据迁移成本为零**。v0.16.2 核心工作量在查询层（`LibraryListQuery`/`list()` 加 projectId 过滤）+ UI 层（分组/徽章/文档页显示）。

## 4. Browser 与 Project 的关系

### 4.1 当前（仅 workspace 关联，与 project 完全无关）

- 存储：单全局文件 `userData/browser-profile/profile.json`（`browser-profile-store.ts:51`），按 `workspaceId` 过滤隔离，**无 project 维度**
- `BrowserHistoryEntry`/`BrowserBookmarkEntry`/`BrowserDownloadRecord`（`dto.ts:1284/1301/1311`）：有 `workspaceId`，**无 projectId**
- `BrowserInstance`（`browser-pane-manager.ts:234`）/ `CreateBrowserInstanceOptions`（`:297`）：有 `workspaceId`，**无 projectId**
- `BrowserWorkspaceSnapshot.tabs[]`（`dto.ts:1351`）：有 `ownerSessionId`，**无 projectId**
- 历史 UI 按天分组（`BrowserCollectionListPanel.tsx:242`），无 project 分组

### 4.2 上下文关联能力（无）

浏览器标签页不能"在 project 上下文中打开"。唯一间接路径：`BrowserInstance.boundSessionId` → `Session.projectId`，但从未物化到 BrowserInstance，也未用于持久化/UI 分组。

### 4.3 关键发现：认知事件层已预留 projectId（未透传）

`BrowserEventProvider` 的 4 个 emit 函数**已有 `projectId?` 参数**（`:50/:91/:123/:152`），`browser-event-builder` 的 `BrowserBaseFields` 也有 `projectId?`（`:24`）。但 `browser-pane-manager.ts` 的 4 个调用点（`:5101/:2825/:2089/:3327`）**从未传入 projectId**。即：认知事件层已就绪，只差调用点透传。

### 4.4 v0.16.3 需要预留什么（v0.16.2 最小预留，纯可选字段）

为 v0.16.3 项目作用域浏览器铺路，v0.16.2 只需加可选字段（参照 `workspaceId?: string | null` 模式，向后兼容）：

| 预留点 | 文件:行 | 改动 |
|---|---|---|
| BrowserInstance 内部接口 | `browser-pane-manager.ts:257` 后 | `projectId?: string \| null` |
| CreateBrowserInstanceOptions | `:303` 后 | `projectId?: string \| null` |
| BrowserInstanceInfo DTO（渲染器可见） | `dto.ts:1269` 后 | `projectId?: string \| null` |
| BrowserHistoryEntry / Bookmark / Download | `dto.ts:1286/1303/1313` 后 | `projectId?: string \| null` |
| BrowserWorkspaceSnapshot.tabs[] | `dto.ts:1370` 后 | `projectId?: string \| null` |
| saveWorkspaceState tabs 白名单 | `browser-profile-store.ts:284` | 透传 projectId |
| toInfo 映射 | `browser-pane-manager.ts:5557` | 透传 projectId |

**不需要预留**：认知事件层（已支持）、profile.json version（v0.16.3 真正使用时再升）、UI 分组逻辑（v0.16.3 再改）。

v0.16.3 实现时：在 4 个 emit 调用点补 `projectId: instance.projectId`（或从 boundSessionId 解析 session.projectId）即可全链路打通。

## 6. v0.16.2 最小实现方案

### 6.1 核心思路

Project 已是稳定容器（id、session 绑定、prompt 注入、cognition 事件 projectId 过滤均已就绪）。**缺口仅在三处**：(a) Library 查询过滤、(b) 项目级活动聚合 UI、(c) 浏览器项目字段预留。全部复用已有能力，无新 Space、无 Workspace 语义变更、无 UI 破坏。

### 6.2 改动清单

**A. Library 项目作用域查询（enabler，最高价值）**
- `packages/shared/src/library/types.ts:159` — `LibraryListQuery` 加 `projectId?: string | string[]`
- `packages/server-core/src/library/LibraryService.ts:256` — `list()` 加 projectId 精确过滤分支（与 search 组合）
- RPC handler（`handlers/rpc/library.ts:48`）已透传 query，无需改
- 迁移：**无**（projectId 已持久化）

**B. ProjectInfoPage「Activity」tab（UI，纯增量）**
- `apps/electron/src/renderer/pages/ProjectInfoPage.tsx`
  - `:34` `TabKey` 加 `'activity'`
  - `:256` 后加 `<TabButton>`
  - `:439` 前加 `{tab === 'activity' && <Info_Section>...}`
- 内容（复用现有数据，lazy-load）：
  - 最近会话：`projectSessions` 按 `lastMessageAt` 排序取 N（零 IPC）
  - 最近文档：`listLibraryDocuments({ workspaceId, projectId, filter:'recent', limit:5 })`（依赖 A）
  - 最近浏览器链接：`listCognitionEvents({ workspaceId, projectId, types:['browser_page_opened'], limit:5 })`（零后端）
- 默认 tab 不变

**C. Library UI 项目徽章（小增强，可选）**
- `apps/electron/src/renderer/components/library/LibraryListPanel.tsx:213` — 裸 id 串改为项目名/色徽章（查 projects atom）
- 可选：文档页 `LibraryDocumentPage.tsx` 加项目归属显示与改绑

**D. Browser 项目字段预留（为 v0.16.3，纯可选字段）**
- `packages/shared/src/protocol/dto.ts` — `BrowserInstanceInfo`/`BrowserHistoryEntry`/`BrowserBookmarkEntry`/`BrowserDownloadRecord`/`BrowserWorkspaceSnapshot.tabs[]` 加 `projectId?: string | null`
- `apps/electron/src/main/browser-pane-manager.ts` — `BrowserInstance`/`CreateBrowserInstanceOptions` 加字段，`toInfo()` 透传
- `apps/electron/src/main/browser-profile-store.ts:284` — `saveWorkspaceState` tabs 白名单加 projectId 透传
- **不实现**项目作用域浏览器逻辑（v0.16.3 在 4 个 emit 调用点补透传即可）

### 6.3 数据迁移方案

**全部无迁移**：
- A：projectId 已持久化在 Library 文档
- B：纯前端聚合，不改存储
- C：纯 UI
- D：全部可选字段，旧 profile.json/config.json 加载后为 undefined，向后兼容

### 6.4 风险点

1. **Library `list()` projectId 过滤与 search 组合**：需确保 projectId 过滤在 search 之前应用、二者 AND 组合。低风险。
2. **Activity tab 性能**：必须 lazy-load（仅进入 activity tab 才拉 library/cognition），复用 assets/memory tab 的 lazy 模式。勿在页面 mount 时全拉。
3. **Browser 预留字段持久化**：`saveWorkspaceState` 白名单必须同步加 projectId，否则保存时静默丢失；`loadWorkspaceState` 已容忍缺失字段（旧 profile）。向后兼容。
4. **cognition 事件 types 过滤**：确认 `browser_page_opened` 是正确的事件类型名（`BrowserEventProvider.ts:41` 的 emit 调用对应类型），需在实现时核对 event type 常量。
5. **悬挂 projectId**：Activity tab 的 library/cognition 查询用 `project.config.id`（当前项目），不存在悬挂问题；session 列表已降级处理。

### 6.5 明确不做（v0.16.2 范围外）

- ❌ Project members / permissions / source bindings / 默认 model
- ❌ 浏览器项目作用域实现（仅预留字段）
- ❌ Workspace 语义变更
- ❌ 新增 Space
- ❌ 移动 session 时切换 workingDirectory（保持现有"仅影响新建默认值"语义）
