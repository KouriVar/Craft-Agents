## 4. Phase 9 实际修复

本节只列 Phase 9 审计期间实际触碰的关键文件/文件组；worktree 中其他 Phase 5–8 改动保持原样。

- 导航、上下文新建、路由与原生浏览器视图：
  `AppShell.tsx`、`MainContentPanel.tsx`、`NavigationContext.tsx`、`route-parser.ts`、`create-resolver.ts`、`BrowserWorkspacePage.tsx`。
- Dynamic Center：
  `components/dynamic/`、dynamic RPC/store/tests。
- 自动化与工作流：
  `AutomationDraftDialog.tsx`、`WorkflowEditor.tsx`、workflow runner/store/approval store/run context、SessionManager、prompt handler、automation config/history、webhook/web monitor。
- 外部事件：
  project lifecycle/RPC、file watcher、`packages/messaging-gateway/src/gateway.ts`。
- 迁移与可靠性：
  `versioned-json-store.ts`、`v020-baseline.ts`、`v020-knowledge.ts`、`v020-automation-config.ts` 及测试。
- 截图 IPC：
  screen capture protocol constants、preload/main/window manager、IPC snapshot、raw-send allowlist。
- 中文与版本：
  7 个 locale、设置/知识库/能力中心文案、13 个 package manifest、`bun.lock`、README、CHANGELOG、0.20.0 release notes。

关键行为变化：

- 正式一级导航收敛为“新建、会话、浏览器、项目、自动化、知识库、动态、技能”，设置与最新动态固定到底部。
- 旧产品深链不再复活旧正式页面。
- Dynamic 权限项不再以通用“已处理”伪成功收口。
- 自动化有限重试真正接入执行路径；会话/连接器工作流节点等待实际 Run Session 完成。
- 工作流审批持久化 continuation；批准/拒绝幂等，重启后可继续；审批节点位于并行汇合之后以避免重放兄弟分支。
- 网页监控、Webhook replay、工作流、Dynamic、搜索、专家、用量及审计文件有显式版本和安全迁移。
- 双 Knowledge/Library 树安全合并；冲突时拒绝覆盖。
- 服务商返回“Model is disabled”时，改为中文的不可重试模型策略错误并引导打开模型设置；不再被含有 `service` 的上游文本误判为可重试的临时服务故障。

## 8. 不得发布项与风险

### P1 — 发布前必须人工完成

1. macOS 同时按左右 Command 的截图链路：辅助功能、屏幕录制、后台唤起、选中会话、聚焦输入框、不自动发送。
2. 在目标 macOS、Windows、Linux 上分别构建、安装和执行最小烟测。
3. 用至少一个真实第三方连接器凭据验证成功路径，并用无效凭据验证失败不会显示成功。

### P2 — 已知非阻塞技术债

1. lint 共 134 条 warning，主要为 React Hook dependencies、legacy localStorage 和无效 eslint-disable。
2. renderer 存在大 chunk 构建警告。
3. 为解析历史持久化状态，内部仍保留 Source/Plugin 导航类型和详情组件；正式导航与旧 URL 已重定向到能力中心，普通用户入口不暴露它们。后续可在确认不再需要历史状态恢复后物理删除。
4. UI 烟测后半段使用隔离 profile。早期上下文新建/浏览器 CRUD 烟测曾在主 profile 留下一个“未命名文档”和浏览器标签状态；依照“不删除用户数据”约束没有代用户清理。用户主 profile 中也保留了迁移前数据副本。
