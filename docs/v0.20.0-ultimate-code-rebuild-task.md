## 你的身份与最终目标

你是 CraftAgent v0.20.0 的总负责人、产品工程师、UI 工程师、Electron 工程师和 QA。你拥有一整晚执行时间。不要只做审计、提建议或写计划；必须直接修改代码、运行应用、验证交互、补齐测试，并持续推进到所有 P0/P1 项完成，或留下有证据的明确阻塞。

当前 v0.20.0 一律视为“未完成”：

最终目标是交付一个 UI 统一、入口明确、设置真实生效、核心功能端到端闭环、可构建、可测试、可重启恢复的 v0.20.0。任何无法完成的能力必须从正式 UI 隐藏或明确标为不可用，不能保留“能点但没用”的假入口。

## 绝对安全规则

当前工作区包含大量未提交修改、删除和未跟踪文件，这些都视为用户资产。

1. 禁止运行 `git reset --hard`、`git clean`、`git checkout -- .`、`git restore .` 或任何可能丢失现有改动的命令。
2. 禁止擅自回退整个分支、覆盖现有文件、删除用户数据或清理 `~/.craft-agent`。
3. 开工前记录：
   - `git status --short`
   - `git diff --stat`
   - 当前分支和 HEAD
   - 未跟踪文件列表
4. 修改前先理解现有 diff。只删除已经证明为废弃、重复或不可达的代码，并记录删除理由。
5. 不得通过删除测试、跳过测试、放宽类型、滥用 `any`、吞掉异常、伪造成功 Toast 或写死 mock 数据换取“通过”。
6. 不得直接在真实用户 profile 上做破坏性验证。使用隔离测试 profile；涉及迁移时先复制备份。
7. 不要盲目全量重写。否认的是当前完成度和交互方案，不是无差别摧毁仍然可靠的底层能力。可复用的实现必须保留并纳入统一架构。

## 完成定义

一个功能只有同时满足以下条件才算完成：

```text
可发现入口
→ 正确 UI 状态
→ 参数校验
→ renderer 调用
→ preload/transport 通道
→ main/server handler
→ domain/service
→ 真实副作用或持久化
→ 成功/失败回传
→ UI 即时同步
→ 关闭重开后仍正确
→ 自动测试 + Electron 人工验证证据
```

缺少任何一段，都不得标记完成。

每个开关、输入框、下拉框和按钮都必须回答：

- 它读的是哪个真实配置字段？
- 改变后调用了哪个 API？
- 数据写到哪里？
- 谁消费这个值？
- 何时生效，是否需要重启？
- 保存失败时 UI 如何回滚或提示？
- 重启 App 后是否保持？
- 多窗口是否同步？
- 是否有自动测试覆盖读、写、消费三端？

如果回答不出来，该控件就是假功能：要么补通，要么从正式 UI 删除。

## Phase 1：先重建 UI 基础，不再逐页堆补丁

目标：建立一套唯一的页面骨架和控件语言，然后让所有模块迁移到这套基础上。

### 1.1 建立唯一组件基线

优先复用并修正现有原生组件：

- `PanelHeader`
- `EntityRow`
- `EntityListEmptyScreen`
- `Info_Page`
- `HeaderIconButton`
- `StyledDropdownMenu`
- `StyledContextMenu`
- 现有 Settings section/row/input/select/switch 组件

禁止每个页面自己写一套卡片、标题、选中态、菜单、空状态和按钮。

统一以下 token：

- 三栏宽度、最小宽度、折叠点
- 行高、页边距、分隔线起点
- 字号、字重、次级文字透明度
- 按钮尺寸、圆角、hover、pressed、focus、disabled
- 菜单圆角、阴影、内距和危险操作
- Loading、Empty、Error、Success、Skeleton
- 浅色、深色和高对比度
- z-index 与 Electron 原生 BrowserView/WebContentsView 遮挡策略

任何新 CSS 值如果与 token 重复，必须改为复用 token。不得靠大量局部 magic number“调到看起来差不多”。

### 1.2 重建页面骨架

逐个修复：

- 会话：作为列表、详情、选择、菜单和输入区的视觉基准。
- 浏览器：标签列表和原生网页层严格限于内容区；任何菜单、Dialog、Popover、Toast 都不能被网页覆盖。
- 项目：列表 + 完整详情；不得用大卡片墙或临时摘要替代详情。
- 自动化：列表 + 详情 + 自然语言创建；未完整可用的 Workflow 编辑器不得暴露。
- 知识库：统一列表、正文详情、编辑和元信息，不重复堆标题和新建按钮。
- 动态：真实列表、筛选、已读状态、关联对象跳转；不得整列空白。
- 技能：专家/技能/连接器共享统一资源列表和完整详情，不得退化为摘要卡。
- 设置：统一设置导航和设置控件，默认选中“通用”。

### 1.3 UI 验收

每个页面至少验证：

- 正常窗口、窄窗口、高窗口
- 浅色、深色
- 默认、hover、pressed、focus-visible、selected、disabled、loading、empty、error
- 鼠标、触控板、右键、键盘
- 每栏独立滚动，无无意义横向滚动
- 中英文长文本不截断关键操作
- 原生网页层不遮挡任何浮层
- 页面切换后标题、列表、详情和动态“新建”同时更新

不要只读 JSX 判断 UI；必须运行 Electron 并截图对比。

## Phase 2：设置中心逐项代码级打通

这是最高优先级。当前注册表存在 14 个设置页面，而普通导航只展示约 9 个。必须区分“正式展示”“高级隐藏”“彻底废弃”，不能只把页面藏起来就当完成。

### 2.1 正式设置页

普通用户导航只保留并彻底打通：

1. 通用
2. 模型
3. 用户记忆
4. 外观
5. 输入
6. 快捷键
7. 空间
8. 账号
9. 权限

对每一页的每一个控件建立设置矩阵，逐项追踪：

```text
控件
→ config key / 数据对象
→ 默认值
→ renderer 本地状态
→ API/IPC/RPC
→ schema/validator
→ storage
→ runtime consumer
→ 即时生效或重启生效
→ 错误处理
→ 重启恢复
→ 测试
```

重点验证：

- 通用：语言、启动行为、更新、通知等是否真实改变应用行为。
- 模型：连接 CRUD、凭据安全存储、连接测试、默认连接、默认模型、思考等级、工作区覆盖与会话覆盖。
- 用户记忆：读取、编辑、保存、清空、作用范围和实际注入 Agent 上下文。
- 外观：浅色/深色/跟随系统、主题持久化、浏览器空白页同步、多窗口同步。
- 输入：发送键、草稿、附件、文本行为等是否被输入组件真实消费。
- 快捷键：注册、冲突、禁用、修改后重注册；双 Command 截图必须显示真实权限和监听状态。
- 空间：名称、目录、默认配置和空间级覆盖是否真实保存并生效。
- 账号：OAuth/连接状态、断开、失败、过期状态，不得本地假登录。
- 权限：模式、规则、访问日志和运行时 pre-tool 检查必须一致。

### 2.2 隐藏页面的处置

逐项处置 `privacy`、`cognition`、`labels`、`messaging`、`server` 等当前仍注册但不在普通导航的页面：

- 若能力仍被产品需要：迁移到对应正式模块或“高级设置”，补齐入口和闭环。
- 若仅供调试：明确开发模式限制，生产构建不可通过普通深链误入。
- 若已废弃：删除路由、组件、注册、文案、无调用 handler、死类型和测试。
- 旧深链必须安全降级到最近的有效设置页，并给出可理解提示，不能白屏。

### 2.3 设置专项测试

必须增加参数化/表驱动测试，至少覆盖：

- 所有正式控件都有合法 config key。
- config schema、默认值、DTO、handler 和 UI 类型一致。
- 修改后 storage 中的值正确。
- runtime consumer 确实读取修改后的值。
- 保存失败不显示成功，不永久停留在错误的乐观状态。
- 重启和多窗口同步。
- 无效旧 route 安全降级。
- 敏感值不进入日志、DOM 明文、普通配置文件或错误消息。

## Phase 3：核心模块端到端闭环

按下面顺序逐项完成。每个对象必须覆盖 Create / Read / Update / Delete 或明确的归档策略。

### 3.1 会话

- 新建、发送、流式输出、停止、重试、排队、草稿、附件。
- 重命名、状态、标签、项目、归档、删除、搜索和筛选。
- 模型、权限、思考等级、工作目录切换真实影响下一次执行。
- 所有错误必须可恢复，重启后会话和运行状态一致。

### 3.2 浏览器

- 新建、导航、前进后退、刷新、关闭、固定和恢复。
- 浏览器工作区和右侧 Agent 面板状态一致。
- 切换到其他模块时原生网页彻底隐藏且不拦截点击。
- 历史、书签、下载和站点权限只保留真正可用范围。

### 3.3 项目

- 自然语言创建项目，自动生成名称但允许用户确认和编辑。
- 项目详情、目录、会话、知识、自动化和长期上下文形成真实关联。
- 编辑、归档、恢复和删除边界清楚；不得误删工作目录文件。
- 项目级模型/专家/权限覆盖真正被会话继承。

### 3.4 自动化

- 自然语言只生成草案，用户确认前不得保存或执行。
- Cron、事件、Webhook、网页监控至少各有一个真实成功路径和失败路径。
- 运行必须创建可追踪的 Run Session。
- 重试、审批、拒绝、重启恢复、最终失败进入动态。
- 未完整打通的可视化 Workflow 从生产 UI 移除，不留半成品入口。

### 3.5 知识库

- 新建、编辑、自动保存、删除/回收、版本、恢复、搜索和引用。
- 由会话生成知识前必须有明确确认。
- 关联项目与权限边界真实有效。
- 重启后内容、版本和索引一致。

### 3.6 动态

- 通知来源必须是真实系统事件，不得用静态演示数据。
- 未读、筛选、静音、固定和清除真实持久化。
- 会话、运行、项目、权限请求的跳转必须定位到具体对象。
- 权限项执行真实批准/拒绝，并处理过期和重复操作。

### 3.7 专家 / 技能 / 连接器

- 专家：创建、复制、编辑、删除、模型、记忆、技能、连接器绑定。
- 技能：安装/创建、读取完整指令、编辑、启停、删除、作用域。
- 连接器：配置、凭据、测试、启停、编辑、删除、失败反馈。
- Agent 运行时必须真正加载所选专家、技能和连接器。
- 删除或失效引用必须有降级策略，不能导致白屏或运行时崩溃。

## Phase 5：系统性验证

### 5.1 自动化门禁

至少运行：

```bash
bun run typecheck:all
bun run lint
bun test
bun run lint:i18n:parity
bun run lint:i18n:coverage
bun run electron:build
```

若全量测试耗时过长，可以阶段中跑定向测试，但最终必须跑完整门禁。所有失败必须修复或以外部依赖证据标记阻塞，不能静默忽略。

### 5.2 Electron 真实烟测

使用隔离 profile，在实际 Electron 中完成：

1. 冷启动和第二次启动。
2. 逐个切换全部一级模块。
3. 逐个执行上下文“新建”。
4. 逐页修改正式设置并验证即时行为。
5. 完全退出再打开，验证持久化。
6. 创建一个项目、一个会话、一份知识、一个专家、一个连接器和一个自动化。
7. 执行一次真实 Agent 会话。
8. 执行一次真实自动化成功和失败。
9. 验证动态中心收到真实事件并能跳转。
10. 在 Browser 页面打开菜单、Dialog、Popover、Toast，检查原生层遮挡。
11. 浅色、深色、窄窗口、高窗口各走最小路径。

每项保存截图、日志或测试输出。没有证据不得在账本中写 `PASS`。

### 5.3 外部条件

以下项目若缺少真实权限或凭据，不得伪造完成：

- macOS 辅助功能与屏幕录制权限下的双 Command 截图。
- 真实第三方 OAuth/连接器成功路径。
- 签名、公证和跨平台安装包。

先完成所有本地可验证部分，再将这些项目标为 `BLOCKED`，写清复现步骤、已经验证到哪一层、缺少什么外部条件。

## 优先级和通宵停止规则

必须按以下优先级工作：

### P0

- 应用能构建、启动、切换所有正式模块。
- 无白屏、崩溃、数据损坏和原生网页遮挡。
- 设置正式 9 页所有可见控件都真实生效，或删除假控件。
- 会话发送与 Agent 执行主链路可用。
- 项目、知识库、自动化、动态、专家/技能/连接器至少完成产品定义中的核心闭环。
- 所有成功提示都来自真实成功响应。

### P1

- UI 全局一致性、响应式、键盘和所有交互状态。
- 完整 CRUD、搜索、筛选、重启恢复、多窗口同步。
- 自动化真实事件、重试、审批和失败闭环。
- 设置旧路由迁移和废弃代码清理。

### P2

- 性能优化、低频高级能力、跨平台细节和非阻塞技术债。

不要为了多做 P2 留下任何 P0/P1 半成品。若一夜无法全部完成，优先交付少而完整的正式能力，并隐藏未完成入口。

只有满足以下任一条件才允许停止：

1. P0/P1 全部通过，完整门禁通过，Electron 烟测有证据。
2. 遇到必须由用户提供的权限、凭据或产品决策；你已完成所有不依赖该条件的工作，并留下精确阻塞说明。
3. 时间耗尽，但必须先保证仓库处于可构建、可启动、不丢数据的状态，并提交真实完成清单和未完成清单。

“代码很多”“问题复杂”“需要后续优化”不是停止理由。

## 最终交付格式

最终回复必须包含：

1. **最终状态**：可发布 / 不可发布。
2. **实际完成**：按模块列用户现在能完成的动作。
3. **设置矩阵结果**：正式设置页逐项 PASS / REMOVED / BLOCKED。
4. **UI 修复**：统一了哪些基础组件，删除了哪些重复实现。
5. **调用链修复**：列出关键 renderer → IPC/RPC → service → storage/runtime 链路。
6. **删除内容**：删除了哪些假功能和死代码，为什么安全。
7. **验证证据**：命令、结果、Electron 场景和截图位置。
8. **仍未完成**：精确到功能、文件/模块、原因和下一步；禁止模糊表述。
9. **Git 状态**：最终 `git status --short` 和 diff 摘要，明确没有覆盖用户原有改动。
10. **发布阻塞**：真实凭据、系统权限、签名/公证等外部门槛。

最后一条原则：宁可明确删除一个未完成入口，也不要保留一个看似完整、实际无效的按钮；宁可交付 8 个完整能力，也不要交付 30 个半成品页面。
